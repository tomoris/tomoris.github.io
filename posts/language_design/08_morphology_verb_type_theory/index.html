言語設計 #08

動詞にあたる内容語

前回は、 WordNet を使って実質的には名詞に相当する内容語を設計した。今回は、動詞にあたる内容語を設計する。名詞に相当する内容語と同様に第一音節を見れば語がわからなくても何かしら推測できるようにしたい。しかし、WordNet に含まれる動詞やその階層を見てみたが、ほとんどフラットな階層であまり設計には役立ちそうになかった。

そこで、動詞の第一音節からx1とx2の WordNet ベースの分類が判定できる設計を考える。具体的には以下の分類を採用する。

  • pa[CV]+ (生物x1が生物x2をxxxする)
    • x1: bV, x2: bV
  • pe[CV]+ (生物x1が生物以外の物理的実体x2をxxxする)
    • x1: bV, x2: dV|nV
  • pi[CV]+ (生物x1がxxxする)
    • x1: bV
  • po[CV]+ (生物以外の物理的実体x1が生物以外の物理的実体x2をxxxする)
    • x1: dV|nV, x2: dV|nV
  • pu[CV]+ (生物以外の物理的実体x1がxxxする)
    • x1: dV|nV
  • ka[CV]+ (生物x1が抽象概念x2をxxxする)
    • x1: bV, x2: gV|mV|rV|zV
  • ki[CV]+ (生物以外の物理的実体x1が抽象概念x2をxxxする)
    • x1: dV|nV, x2: gV|mV|rV|zV
  • ku[CV]+ (抽象概念x1が抽象概念x2をxxxする)
    • x1: gV|mV|rV|zV, x2: gV|mV|rV|zV

たとえば、第一音節が pa であれば、生物x1が主格・動作主として生物x2を対格・被動者または主題として何かしらの動作をすることがわかる。

動詞も前回説明したように英語から借用する。例をあげると、英語の「love」は「parobe」で「生物x1が生物x2を愛す」になる。

型理論

x1とx2の WordNet ベースの分類が判定できることは、プログラミング言語の型のような働きを意味する。以下の Python の関数(述語)では引数(項)として整数型と文字列型の変数を受け取り、ブール型の値(True or False)を返す。

def func(x1: int, x2: str) -> bool:
    return x1 > 0 and x2 == "abc"

これと似たようにこの言語の動詞は引数x1とx2の型にあった値を受け取り、ブール型の値を返すイメージに近い。より厳密にはその他の意味役割の入力も許し、引数の省略を許すので、 Python コードで表現するなら以下のようになる。

class LivingThing:
    def __init__(self, word):
        self.prefixes = ["ba", "be", "bi", "bu"]
        self.word = word

class PhysicalObject:
    def __init__(self, word):
        self.prefixes = ["da", "di", "du", "na", "ne", "ni", "no", "nu"]
        self.word = word

def pe_func(
    x1: LivingThing | None = None,
    x2: PhysicalObject | None = None,
    instrumental_arg: PhysicalObject | None = None,  # 具格に相当するもの
    ...  # その他この言語で採用する格・意味役割
) -> bool:
    ...

ここで注目してほしいのは、x1に生物系(LivingThing)が入るなら、項抽出と名詞に相当する語で表したとき、その語の第一音節は b から始まるはずだという点である(前回の WordNet の分類を参照)。同様に、x2や具格に生物以外の物理的実体(PhysicalObject)が入るなら d か n から始まるはずである。具体例として「私はリンゴをフォークを使って食べる」という文を書いてみる。「私」に相当する代名詞 p私p_{\text{私}}p私​ を使って以下のように表現できる。

「peheta c主格 p私 c対格 rx2抽出c_{\text{主格}} \ p_{\text{私}} \ c_{\text{対格}} \ r_{\text{x2抽出}}c主格​ p私​ c対格​ rx2抽出​ nohapare c具格 rx2抽出c_{\text{具格}} \ r_{\text{x2抽出}}c具格​ rx2抽出​ dahoraka」

「peheta」は「食べる(eat)」、「nohapare」は「リンゴ(apple)」、「dahoraka」は「フォーク(fork)」である。x2が no から始まる語で構成されており、具格に入る項は da で始まる語で構成されており、特に違和感のない文になる。

この文をあえて項の型が合わない文に変えてみる。

「peheta c主格 p私 c対格 rx2抽出c_{\text{主格}} \ p_{\text{私}} \ c_{\text{対格}} \ r_{\text{x2抽出}}c主格​ p私​ c対格​ rx2抽出​ rihorada c具格 rx2抽出c_{\text{具格}} \ r_{\text{x2抽出}}c具格​ rx2抽出​ dahoraka」

「nohapare」を「言葉(word)」を表す「rihorada」に変更した。x2に生物以外の物理的実体が入るところ、抽象概念が入っている。無理やり訳すと、「私は言葉をフォークで食べる」になるだろうか。これは型検査でエラーになる。

このように VSO もしくは VOS 語順で V の第一音節を聞いただけで項に現れる大まかな分類がわかるようになり、聞き手の理解コストを下げるだろう。また、逆に明らかにおかしな項に関しては型検査で自動的にはじくことができる。

この設計の注意点にも触れておきたい。同じ「食べる」という語でも字面が異なってしまうことがある。WordNet では生き物としての魚(fish.n.01)は「entity.n.01 -> physical_entity.n.01 -> object.n.01 -> whole.n.02 -> living_thing.n.01 -> organism.n.01 -> animal.n.01 -> …」であり、第一音節は bi である。一方、食べ物としての魚(fish.n.02)は「entity.n.01 -> physical_entity.n.01 -> matter.n.03 -> solid.n.01 -> food.n.02 -> …」であり、第一音節は no である。そのため、踊り食いのように魚を生きたまま食べる場合と、食材として食べる場合では、生物x2をとる paheta と peheta を使い分けないといけない。これは発話者にとっては負担が大きいだろう。

比喩・型の上書き

型検査を厳密に適用してしまうと、「まるで石のような固いリンゴだった。私は石を食べたようだ。」のような比喩表現を使えない。そこで、項の型を上書きして、Python や TypeScript でいう Any 型のように扱える仕組みを導入したい。型の上書きを行う語 o型の上書きo_{\text{型の上書き}}o型の上書き​ を用いると、上の型検査に引っかかる文は以下のように修正できる。

「peheta c主格 p私 c対格 o型の上書き rx2抽出c_{\text{主格}} \ p_{\text{私}} \ c_{\text{対格}} \ o_{\text{型の上書き}} \ r_{\text{x2抽出}}c主格​ p私​ c対格​ o型の上書き​ rx2抽出​ rihorada c具格 rx2抽出c_{\text{具格}} \ r_{\text{x2抽出}}c具格​ rx2抽出​ dahoraka」

この文は「私は本来は物理的実体ではない言葉を物理的実体とみなして食べる」と解釈できる。言葉を文字どおりに食べることはできないので、比喩表現だとわかる。そこから発展して、以下の文のように、型の上書きがなくても型検査に通る項に型の上書きを使う場合を考える。型検査に通るはずなのにわざわざ型を上書きするなら、本来は項に来ないものを使っている、つまり比喩表現なんだと解釈する。

「peheta c主格 p私 c対格 o型の上書き rx2抽出c_{\text{主格}} \ p_{\text{私}} \ c_{\text{対格}} \ o_{\text{型の上書き}} \ r_{\text{x2抽出}}c主格​ p私​ c対格​ o型の上書き​ rx2抽出​ databare c具格 rx2抽出c_{\text{具格}} \ r_{\text{x2抽出}}c具格​ rx2抽出​ dahoraka」

「databare」は「テーブル(table)」で、da から始まるので本来は peheta のx2に入れても型検査に通る。それでも型を上書きしているので、テーブルを文字どおりに食べるのではなく、何かの比喩として「テーブルを食べる」と言っているのだと解釈する。

ちなみに、比喩や慣用表現のために項を変換するか、動詞を変換するかの選択肢がある。「時間を食う」は「時間」の型を上書きするか、本来はなかった動詞 kaheta を作るというパターンもありえる。まだ設計が固まってるわけではないが、本来はなかった動詞を作るよりは項の型を上書きする方が理解コストが小さくなり、そちらを積極的に採用すべきだと考えている。
