言語設計 #01

文法クラス

習得、理解コストが小さい統語とはどのようなものだろうか。この言語では、計算機科学における計算量という物差しを使うことにした。計算量とは、アルゴリズムの効率性を測るための尺度であり、主に時間計算量と空間計算量に分けられる。簡単に説明すると、時間計算量とはアルゴリズムのステップ数を指し、空間計算量とはアルゴリズムが使用するメモリ量を指す。さらに最悪計算量や平均計算量という定義もある。最もステップ数やメモリ量が大きくなる場合を想定したものが最悪計算量で、平均的な場合を対象にしたものが平均計算量である。特に言及がない場合は、最悪計算量で考える。計算量の大雑把な見積もりとして big-OOO 記法を用いる。big-OOO 記法では、入力サイズが非常に大きくなる場合に支配的な項だけを残し、定数や低次の項は無視する。関数 f(n)=5n3+4n2−n+1f(n) = 5n^3 + 4n^2 - n + 1f(n)=5n3+4n2−n+1 の計算量は O(n3)O(n^3)O(n3) である。

この計算量が小さくなる文法は、人間にとっても習得しやすく理解しやすい統語だとみなし設計する。

チョムスキー階層

チョムスキー階層とはチョムスキーが提案した形式文法の包含関係に基づく階層構造である。形式文法は、文字列を生成するための規則体系で、以下の要素から構成される。

  • 終端記号 Σ\SigmaΣ：実際に文字列に現れる文字や単語
    • a,b,c,...∈Σa, b, c, ... \in \Sigmaa,b,c,...∈Σ
    • なお、 ϵ\epsilonϵ は空文字列を表し、終端記号ではない
  • 非終端記号 NNN：生成過程で置換される記号
    • S,A,B,C,...∈NS, A, B, C, ... \in NS,A,B,C,...∈N
  • 開始記号：生成の出発点となる記号
    • SSS
  • 生成規則 RRR：非終端記号を他の記号列に置換するルール

そして制約の強さや表現力によって4つに分類される。

  • タイプ3：正規文法
    • 右正規文法は生成規則が以下の形式に従う
      • A→aA \to aA→a
      • A→aBA \to aBA→aB
      • A→ϵA \to \epsilonA→ϵ
    • 左正規文法は生成規則が以下の形式に従う
      • A→aA \to aA→a
      • A→BaA \to BaA→Ba
      • A→ϵA \to \epsilonA→ϵ
    • 例：L={an∣n>0}L = \{a^n | n > 0\}L={an∣n>0}
    • 最悪時間計算量： O(n)O(n)O(n)
  • タイプ2：文脈自由文法
    • 生成規則が以下の形式に従う
      • A→αA \to \alphaA→α
    • 例：L={anbcn∣n>0}L = \{a^n b c^n | n > 0\}L={anbcn∣n>0}
    • 最悪時間計算量： O(n3)O(n^3)O(n3)
  • タイプ1：文脈依存文法
    • 生成規則が以下の形式に従う
      • αAβ→αγβ\alpha A \beta \to \alpha \gamma \betaαAβ→αγβ
      • ただし、 γ≠ϵ\gamma \neq \epsilonγ=ϵ
    • 例：L={anbncn∣n>0}L = \{a^n b^n c^n | n > 0\}L={anbncn∣n>0}
    • 所属判定問題：PSPACE完全
  • タイプ0：無制限文法
    • 生成規則が以下の形式に従う
      • γ→α\gamma \to \alphaγ→α
      • ただし、 γ≠ϵ\gamma \neq \epsilonγ=ϵ
    • 最悪時間計算量：所属判定問題は決定不能(有限時間では停止しないケースが存在する)

ただし、α,β,γ\alpha, \beta, \gammaα,β,γ は終端記号や非終端記号からなる文字列とする。最悪時間計算量にでてくる nnn は入力系列の長さである。タイプの数字が大きい文法は小さい文法でも表現でき、包含関係にある。

自然言語はどこに位置するか

  • 太郎が おはよう と言った
  • 太郎が 次郎が おはよう と言った と聞いた
  • 太郎が 次郎が 三郎が おはよう と言った と言った と聞いた
  • 太郎が 次郎が 三郎が 四郎が おはよう と言った と言った と言った と聞いた

この例文は長くなれば不自然に感じられるが、意味解釈が可能な文である。「太郎が」や「次郎が」などを aaa とし、「おはよう」を bbb 、「と言った」や「と聞いた」を ccc としたとき、 {anbcn∣n>0}\{a^n b c^n | n > 0\}{anbcn∣n>0} という形式になっている。そのため、日本語は正規文法では表現しきれず、文脈自由文法以上の表現力が求められる。上の例文を受理する生成規則は以下になる。

  • S→NがSと言ったS \to N \text{が} S \text{と言った}S→NがSと言った
  • S→NがSと聞いたS \to N \text{が} S \text{と聞いた}S→NがSと聞いた
  • S→おはようS \to \text{おはよう}S→おはよう
  • N→太郎∣次郎∣...N \to \text{太郎} | \text{次郎} | ...N→太郎∣次郎∣...

自然言語が文脈自由文法の範囲を超える例として、スイス・ドイツ語における目的語に対する格支配がある。具体的には挙げないが {ambn(x)cmdn∣n>0,m>0}\{a^m b^n (x) c^m d^n | n > 0, m > 0\}{ambn(x)cmdn∣n>0,m>0} の形式になる。これは文脈依存文法で表現できる。このように一部、文脈自由文法で表現できない文が存在するが、ほとんどの文は文脈自由文法の範囲で表現できる。そのため、自然言語は文脈自由よりも表現力が高いが、文脈依存文法ほどは高くない、弱文脈依存文法や半線形増加文法の範囲ではないかと考えられている。弱文脈依存文法の代表例である木接合文法(TAG)の構文解析は O(n6)O(n^6)O(n6) の計算量になる。

人工言語の統語をどの文法で設計すべきか

人工言語の統語は文脈自由文法の範囲で定義できる方がいいだろう。弱文脈依存文法まで範囲を広げると計算量が大きくなりすぎる。正規文法の範囲になると、anbna^n b^nanbn のような対応する個数を記憶することができず、入れ子構造などを表現できない。

文脈自由文法のなかでもさらに細分化したクラスを考えることができる。プログラミング言語の統語を設計するときによく使われるのは LL(kkk) と LR(kkk) である。LL とは Left-to-right scan, Leftmost derivation の頭文字で、入力系列を左から右に読み、左端導出を行う。トップダウンに解析結果がわかる。LR とは Left-to-right scan, Rightmost derivation in reverse の頭文字で、入力系列を左から右に読み、右端導出を逆にたどる。ボトムアップに解析結果がわかる。たとえば、 以下の生成規則があったとする。

  • S→E DS \to E \ DS→E D
  • E→A B CE \to A \ B \ CE→A B C
  • A→aA \to aA→a
  • B→bB \to bB→b
  • C→cC \to cC→c
  • D→dD \to dD→d

入力系列 a b c da \ b \ c \ da b c d を構文解析するとその解析結果は [S [E [A a] [B b] [C c]] [D d]][_S \ [_E \ [_A \ a] \ [_B \ b] \ [_C \ c]] \ [_D \ d]][S​ [E​ [A​ a] [B​ b] [C​ c]] [D​ d]] になる。LL 法ではまず [S ?][_S \ ?][S​ ?] が導出され、 [S [E ?] [D ?]][_S \ [_E \ ?] \ [_D \ ?]][S​ [E​ ?] [D​ ?]], [S [E [A ?] [B ?] [C ?]] [D ?]][_S \ [_E \ [_A \ ?] \ [_B \ ?] \ [_C \ ?]] \ [_D \ ?]][S​ [E​ [A​ ?] [B​ ?] [C​ ?]] [D​ ?]], [S [E [A a] [B ?] [C ?]] [D ?]][_S \ [_E \ [_A \ a] \ [_B \ ?] \ [_C \ ?]] \ [_D \ ?]][S​ [E​ [A​ a] [B​ ?] [C​ ?]] [D​ ?]] の順に解析が進んでいく。LR 法では [A a][_A \ a][A​ a], [A a] [B b][_A \ a] \ [_B \ b][A​ a] [B​ b], [A a] [B b] [C c][_A \ a] \ [_B \ b] \ [_C \ c][A​ a] [B​ b] [C​ c], [E [A a] [B b] [C c]][_E \ [_A \ a] \ [_B \ b] \ [_C \ c]][E​ [A​ a] [B​ b] [C​ c]] の順に解析が進んでいく。kkk はいくつ先読みするかを表しており、特に k=1k=1k=1 がよく使われる。

LL 法でも LR 法でも事前に解析に用いる表を生成する。LR 法は LL 法に比べ、解析表は大きくなりやすく、解析アルゴリズムも複雑である。そのため解析表を小さくする工夫をした SLR(kkk) や LALR(kkk) もよく使われる。LL(kkk), SLR(kkk), LALR(kkk), LR(kkk) のいずれも最悪時間計算量は O(n)O(n)O(n) だが、表現できる文法の範囲は LL(kkk) ⊂\subset⊂ LR(kkk) かつ SLR(kkk) ⊂\subset⊂ LALR(kkk) ⊂\subset⊂ LR(kkk) である。また、 LL(kkk) ⊂\subset⊂ LL(k+1k+1k+1) のように同一の解析法なら kkk が大きい方が文法クラスとして表現力が高い。

今回の人工言語では LL(1) の範囲で設計することが適切だと考える。アルゴリズムもシンプルであり、解析表も小さいため人が解析するときも容易である。トップダウン解析なのも漸進的に解析できて都合がよい。ボトムアップ解析だと最後まで読まないと文全体の構造がわからない。トップダウン解析では文の途中まで読んだ時点で、それまでの構造を確定できる。文を最後まで待たなくても理解を進められ、人の認知負荷を下げられる。

LL(1) を採用することのデメリット

LL(1) を採用することに決めたが、表現できない生成規則にも触れておく。LL(1) では左再帰を表現できない。たとえば以下の生成規則は LL(1) では表現できない。

  • S→a AS \to a \ AS→a A
  • A→A cA \to A \ cA→A c
  • A→bA \to bA→b

左再帰 A→A cA \to A \ cA→A c が含まれている。LL(1) で解析できるなら、1つ先読みすると A→A cA \to A \ cA→A c か A→bA \to bA→b のどちらを適用すればいいかわかるはず。しかし、

  • A→A cA \to A \ cA→A c: 右辺の先頭である AAA は最終的に bbb になる
  • A→bA \to bA→b: bbb が先頭になる

これではどちらの生成規則を適用すればいいかわからない。

左再帰の生成規則は左再帰を用いない規則に書き換えることもできる。

  • A→A αA \to A \ \alphaA→A α
  • A→βA \to \betaA→β

この生成規則があったとき、以下のように変形すると左再帰除去することができる。

  • A→β A′A \to \beta \ A'A→β A′
  • A′→α A′A' \to \alpha \ A'A′→α A′
  • A′→ϵA' \to \epsilonA′→ϵ

ただし、 α≠ϵ\alpha \neq \epsilonα=ϵ とする。

LL(1) を採用すると、左再帰を含む生成規則を扱いたい場合は、生成規則を見直し、左再帰除去する必要がある。生成規則の数が多くなってくると、左再帰が入り込むことがあり、設計の難易度が高まる。

習得、理解コストが小さい統語への異なるアプローチとして簡潔さ(succinct)がある。簡潔さとはどれだけ小さいデータやモデルサイズで表現できるかである。言語モデルでは RNN より Transformer がよく用いられる。Transformer は RNN よりも受理できる言語の範囲が狭いが小さなサイズで複雑なパターンを表現できる1。

LL(1) の解析アルゴリズム

構文解析するときは、スタックと解析表を用いる。次の生成規則を持つ文法を例に説明する。

  • S→a A B bS \to a \ A \ B \ bS→a A B b
  • A→cA \to cA→c
  • A→ϵA \to \epsilonA→ϵ
  • B→dB \to dB→d
  • B→ϵB \to \epsilonB→ϵ

まず、生成規則から解析表を生成する。ここでは解析表の生成アルゴリズムは省略する。$\char36 $ は特殊な終端記号でスタックと入力の最後を表す。

aaabbbcccddd$\char36 $
SSSS→a A B bS \to a \ A \ B \ bS→a A B b
AAAA→ϵA \to \epsilonA→ϵA→cA \to cA→cA→ϵA \to \epsilonA→ϵ
BBBB→ϵB \to \epsilonB→ϵB→dB \to dB→d

具体的な入力「 a d b $a \ d \ b \ \char36 a d b $ 」をこの文法で解析してみる。スタックの初期状態は [SSS, $\char36 $] である。

  • 入力：「 a d b $a \ d \ b \ \char36 a d b $ 」
  • スタック：[SSS, $\char36 $]

まず入力から最初の1文字を読むと aaa が得られる。スタックの先頭を消費すると SSS が得られる。解析表から aaa と SSS に対応する生成規則を見ると S→a A B bS \to a \ A \ B \ bS→a A B b が得られる。スタックに生成規則の右辺を逆順に投入する。

  • 入力：「 a d b $a \ d \ b \ \char36 a d b $ 」
  • スタック：[aaa, AAA, BBB, bbb, $\char36 $]

そして、入力の先頭 aaa とスタックの先頭 aaa が一致するので、入力からもスタックからも消費する。

  • 入力：「 d b $d \ b \ \char36 d b $ 」
  • スタック：[AAA, BBB, bbb, $\char36 $]

この一連の流れを続けると解析できる。次に、現在の入力の先頭は ddd 、スタックを消費して AAA を取りだすと解析表から A→ϵA \to \epsilonA→ϵ が得られる。生成規則の右辺をスタックに投入する。

  • 入力：「 d b $d \ b \ \char36 d b $ 」
  • スタック：[ϵ\epsilonϵ, BBB, bbb, $\char36 $]

スタックの先頭が ϵ\epsilonϵ ならそのまま消費できる。

  • 入力：「 d b $d \ b \ \char36 d b $ 」
  • スタック：[BBB, bbb, $\char36 $]

同様に続ける。

  • 入力：「 d b $d \ b \ \char36 d b $ 」
  • スタック：[ddd, bbb, $\char36 $]

ddd が一致するので消費する。

  • 入力：「 b $b \ \char36 b $ 」
  • スタック：[bbb, $\char36 $]

bbb が一致するので消費する。

  • 入力：「 $\char36 $ 」
  • スタック：[$\char36 $]

$\char36 $ が一致するので消費する。

  • 入力：「 」
  • スタック：[]

入力もスタックも空になったので解析成功である。

これ以上ステップを進められないのに入力やスタックにまだ記号が存在する場合に解析エラーとなり、入力がその文法では受理できないことを示す。たとえば、入力：「 a d a b $a \ d \ a \ b \ \char36 a d a b $ 」は途中までは同じステップだが、 ddd の一致で消費したあとの状態は以下になる。

  • 入力：「 a b $a \ b \ \char36 a b $ 」
  • スタック：[bbb, $\char36 $]

スタックの先頭が終端記号であり、入力の先頭と一致しないのでここで停止し、受理しないことがわかる。
